# Contributing

1. Read `AGENTS.md`, `HANDOFF.md`, and the applicable architecture docs.
2. Find an existing Issue and link the change to it. Do not start duplicate work.
3. Keep changes within the Issue. Propose architectural changes in an ADR first.
4. Add/update tests for behaviour; run and report only checks actually executed.
5. Update docs and `HANDOFF.md` for significant work.
6. Never commit credentials, user data, cloned upstream source, or hidden session reasoning.
7. PRs should state scope, linked Issue, design impact, verification commands/results, security/privacy impact, and known limitations.

The project licence is pending. Until decided, do not copy or redistribute upstream code.
